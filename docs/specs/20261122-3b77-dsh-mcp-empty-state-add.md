# dsh-mcp Dock 空态添加入口（推翻 D4：面板头常驻钮含空态）

## 问题陈述

空清单态（watch 首批已到且列表为空）的面板只渲染虚线框引导文案，无任何按钮或表单入口——用户想接入第一个 MCP server 时必须切回会话输 `/mcp add` 或用自然语言指挥助手。这条约束是 round 1 的有意拍板 D4（spec need20261118-11f8-20261118-0de6 FR-5、测试 AC4 锁死）。发起人 2026-11-22 推翻 D4：空清单恰恰是最需要添加入口的时刻，且非空态已有完整的头部「添加」钮与展开表单，空态继续禁入没有收益。

## 方案

空态与非空清单态统一为同一面板骨架：面板头恒渲染（标题「MCP Servers」+ 计数「0 项」+「添加」常驻钮），虚线框只剩引导文案（内容逐字不变）。点击头部「添加」展开既有同一张添加表单，提交走既有写通道，成功后 watch 投影把面板自动带入非空清单态。

三处契约同步反转：

1. 实现面：空态渲染分支补面板头与添加表单（表单机制复用，零新写路径）。
2. 契约面：原 FR-5/D4「空态无按钮无表单入口」自本 spec 起废止（原 spec 已 done 不回改，推翻记录在本 spec 备注）。
3. 测试面：AC4「空态树不得出现任何交互元素」断言反转为「空态含头部添加钮与添加表单、引导文案齐备」。

## 用户故事

- 作为 dsh web 使用者，我想要空清单时面板头部就有「添加」按钮，以便不切回会话也能直接开始接入第一个 MCP server。
- 作为 dsh web 使用者，我想要空态与非空态结构一致（同一面板头、同一张添加表单），以便首次添加与日常添加共用同一套操作心智。

## 实现决策

- **面板头恒渲染（本 spec 核心决策，推翻原 D4）**：空态（首批已到且 server 视图为空）渲染与非空清单态完全同构的面板头——标题 + 计数（`0 项`）+「添加」primary 常驻钮，沿用同一交互属性钩子（`data-mcp-add-open`）。虚线框引导文案保留且内容逐字不变：会话内 `/mcp add` 与对话式添加仍是写通道之外的合法方式，文案照常指路。加载态（首批未到）区分契约不变：仍渲染 skeleton、无面板头无添加入口。
- **表单与写通道零新增**：空态点「添加」展开的是既有同一张添加表单（元素树恒在、CSS 可见性收起/展开的既有机制），提交沿既有写通道语义（管理服务单点共调的 addServer），零新写路径；提交成功后 watch 投影更新，空态自动转非空清单态，无专门状态迁移逻辑。
- **偏离设计记录**：design 0004 决策 7（空态无按钮，D4 拍板快照）自本 spec 起偏离，理由见问题陈述；design 产物是对已批准事实的快照不回改，偏离只记于此。design 0004 其余布局决策（决策 1–6、8–9）不动。
- **版本记账**：插件包版本 bump（具体号归实现），发布沿 plugin-assets.md §1.4 双包顺序与插件 MAINTAINER.md 维护者配方。

## 测试决策

- **seam 清单**：①替身契约单测——空态形态断言反转（`data-mcp-servers: empty` 树含头部添加钮与添加表单属性钩子、引导文案齐备）；②空态交互单测——空态点添加展开表单、提交驱动既有写通道替身（addServer 被调）；③异常流单测——空态表单提交被拒时行内错误反馈呈现（既有 addNote 反馈机制在空态同生效）；④加载态回归——首批未到仍为 skeleton 无面板头；⑤既有全量回归零修改通过（非空态/错误降级/行内编辑/启停移除契约不变，e2e 集成不锁空态面板形态、应零修改通过）。
- **既有先例**：`test/unit/dsh-mcp-dock-readonly.test.ts` AC4 两条空态断言（引导文案齐备、无交互元素）——本 spec 反转后者、保留并扩展前者；加载态/错误降级断言同文件先例。
- **人工段**：真浏览器空态浏览与空态添加走查（浅色/深色各一遍）截图留痕，沿 round 2 FR-1 人工段口径，不引入浏览器自动化。

## 验收场景

- [FR-1 | 工单级] Given 空清单态（首批已到且为空），When 渲染，Then 面板头呈现（标题 + 计数 `0 项` + `data-mcp-add-open`「添加」钮），虚线框引导文案内容与原契约逐字一致。
- [FR-2 | 工单级] Given 空清单态，When 点击头部「添加」，Then 既有添加表单在面板头下展开（同一 `data-mcp-add-form` 钩子），字段结构与非空态完全一致。
- [FR-3 | 工单级] Given 空态展开的添加表单，When 填写并提交合法草稿，Then 走既有写通道（addServer 同源调用），成功后清单转非空态（面板头计数更新）。
- [FR-4 | 工单级] Given 空态表单提交被拒（如名称与既有 server 冲突），When 提交，Then 行内错误反馈呈现、已填字段保留，与既有非空态失败反馈形态一致。
- [FR-5 | 工单级] Given watch 首批未到（加载态），When 渲染，Then 仍为 skeleton 行 + 读取提示，无面板头无添加入口（空态与加载态区分契约不变）。
- [FR-6 | 工单级] Given 非空清单态与错误降级态，When 全量回归，Then 渲染与断言零变化（本变更只动空态分支）。
- [FR-7 | 集成级 | 人工：浏览器渲染与交互需真浏览器观察（round 1 D6 口径延续）] Given 真实 dsh web 会话空清单，When 人工浏览并从空态走通添加全流程，Then 面板头与表单可用、添加成功后列表出现新 server，截图留痕。
