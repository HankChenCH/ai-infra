# 项目蓝图 round 1：蓝图维护技能与四点接线（单入口退化形态全链）

## 问题陈述

套件消费项目的设计决策散在 need / spec / design / adr 各类轮次产物里，ADR 零散不关联，人对系统缺乏总体认知；全新 AI 会话理解项目要翻多个产物自行拼装，新人接手听不到设计原则与取舍的成体系解释，开发会话没有权威设计参照可依。need 20261124-a727 已定蓝图能力全形态（18 项拍板），design 20261124-325d 已批分析段（走查暴露缺口 4 条）；本轮把能力落成实物：蓝图维护技能 + 四处既有技能接线，单入口退化形态先跑通全链。

## 方案

新增**蓝图维护技能 dev-blueprint**（dev 家族、按需服务定位同 dev-research / dev-release：不进 sdlc next-mode 路由表），承载五过程：立骨架（新立项路）、存量汇合、轮次回写、拆册与对账、施工装载面计算（判定规则文本）。产物 = `docs/blueprints/` 蓝图集（知识档轻产物：无 frontmatter 状态机、不进 check.sh validate——门禁零改动）。四处既有技能薄联动：dev-design 分析批准后亮牌立骨架、setup-reconstruct 出口亮牌汇合、dev-accept 蒸馏扩第五路蓝图回写、dev-implement 开工装载最小必要面；AGENTS.md 加蓝图指针。治理文档先行（套件蓝图 §11 新条目 → docs/skills.md → 编目 → 技能），静态守护测试兜底接线不回退。本轮 = 单入口退化形态全链；多入口完整目录结构深化与广谱漂移检测留 round 2。

本轮范围（已确认 2026-11-24）：单入口退化形态全链，FR-1…FR-9 全覆盖（FR-3 多入口、FR-9 术语按入口归册以退化形态场景承载）；缺口 1 / 2 / 3 落本轮（归属登记载体、回写落册规则、存量入口识别口径），缺口 4 广谱漂移检测列 round 2 下一轮建议。

## 用户故事

1. 作为项目负责人，我想要 design 分析走查批准后经亮牌确认立起蓝图骨架，以便设计意图当场固定成全项目真相源。
2. 作为存量项目接入者，我想要 setup-reconstruct 完成后把逆向产物汇合成首版蓝图，以便不重走设计过程也能得到理解入口。
3. 作为开发会话（施工读者），我想要开工时只装载与本票改动面相关的蓝图册，以便以最小上下文拿到权威设计参照。
4. 作为验收编排，我想要验收通过时该轮耐久变化自动折进对应蓝图册并留修订记录，以便蓝图随轮次保鲜不腐化。
5. 作为读者（AI 新会话 / 新接手的人），我想要读主册 + AGENTS.md 即答核心设计问题、听懂设计原则与取舍，以便不翻轮次产物。
6. 作为项目负责人，我想要单册膨胀时被亮牌建议拆册，以便蓝图不爆炸。
7. 作为项目负责人，我想要 ADR 被立或被取代时蓝图被亮牌提示回写，以便决策链不过期。

2. **新技能 dev-blueprint**：SKILL.md + references/ 两级结构对齐既有技能；按需服务定位——sdlc next-mode 路由表零改动（先例：dev-research / dev-release / dev-docs 不加行）；触发面 = 三处联动亮牌 + 用户手动。
3. **蓝图集结构（本轮落地面）**：docs/blueprints/ 下项目主册 + 全局册（按需）+ 模块册（按需，一册对应一个改动面口径模块）。单入口退化（need D16）：入口判定亮牌机制本轮接线，判定结果单入口或不设入口时不建入口层。design 数据模型 BOOK 的本轮字段子集：book_type ∈ {项目主册, 全局册, 模块册}、entry_slug 恒空（多入口结构 round 2 启用）。
4. **主册自含核心与六类承载**（need D6 / FR-4）：主册节 = 定位与边界 / 架构分层与模块地图 / 关键决策关联 / 术语节 / 修订记录段（演进史）；分册叙述与取舍自含，实现细节与过程索引指回轮次产物（need/spec/design/adr 文件路径）。
5. **决策关联层**（FR-5 / D18）：每条决策记「现状 + 为什么 + 取舍」叙述 + 指回 adr 文件；superseded 链以「被某 ADR 取代（adr 指针）」行内承载（design 对象模型决策条目取代自关联的文本化）。ADR 文件与 docs/adrs/ 机制零改动。
6. **诞生联动两路**（FR-1 / FR-2 / D12）：dev-design 分析形态走查批准（第一道 approved 门）后亮牌建议调 dev-blueprint 立骨架——用户确认才动、亮牌可拒绝；setup-reconstruct 出口亮牌建议汇合逆向产物（逆向 need / 逆向 ADR / 折叠内容）成首版。亮牌话术在 dev-design / setup-reconstruct 出口与蓝图 §11 条目同句落盘。不绑 setup-workspace（need D12）。
7. **存量入口识别口径（缺口 3 拍板）**：dev-blueprint 汇合时从逆向产物与代码结构列入口候选，用户拍板确认清单，禁止代挑；判属争议亮牌列候选 + 拍板（need E4）。
8. **模块归属登记与施工装载命中（缺口 1 拍板，退化形态落地面）**：登记载体 = 项目主册「模块地图」节（模块清单，口径 = dev-plan 改动面同款：目录或模块名）+ 共享模块清单行（round 2 入口级归属的前身）；dev-implement 装载命中 = 本票改动面条目与模块地图同口径匹配：命中 → 装对应模块册 + 主册；未命中（未登记模块）→ 只装主册 + 亮牌建议补登记，不拦截开工。
9. **蒸馏第五路回写（FR-8 / D12，缺口 2 拍板）**：dev-accept §4 蒸馏四路扩五路——⑤ 蓝图回写：按落册判定折进对应册 + 主册修订记录段追加一行（版本 / 日期 / 一句摘要）。落册判定规则 = 全局面（跨模块架构原则、全局决策）折项目主册对应节或全局册；模块面折对应模块册；模块册不存在 → 亮牌建议建册，拒绝则折全局册留痕。ADR 0002 固定序不破（第五路在蒸馏步内，先于清扫）；蓝图不进 validate，回写后由 dev-blueprint 对账自查代替（实现决策 13）。
10. **ADR accepted 亮牌与权威序（FR-8 / D12 / D8）**：dev-design 置 ADR accepted 时亮牌「蓝图待回写」并建议调 dev-blueprint——round 1 漂移检测仅此一类（supersede 冲突），广谱检测（评审轴对照蓝图 / 验收走查 / 巡检）留 round 2（缺口 4）；漂移信号本轮载体 = 亮牌动作 + 回写后主册修订记录留痕（持久标记载体 round 2 与广谱检测同批）；权威序纪律（蓝图与最新轮次产物冲突以轮次产物为准）落 dev-blueprint 正文与蓝图 §11 条目。
11. **施工装载与 AGENTS 指针（FR-7 / D13 / D17）**：dev-implement 装载上下文补开工装载句（实现决策 8 规则）；dev-review / dev-accept 补按需装载句；setup-workspace assets 的 AGENTS 模板项目速览区补蓝图指针行模板（新项目开箱含位，指向 docs/blueprints/，含入口索引占位——本轮单入口时为退化形态）；既有项目指针由 dev-blueprint 立骨架时写入 AGENTS.md 非哨兵区。skills/ 技能实物落盘轮（票 20261124-f9e5）同批把根 AGENTS.md 仓库概述的技能计数 31 → 32（双态同步的文档面，非门禁对账项；运行中修订 2026-11-24）。
