# static-anchor-guard.md —— 静态锚定守护的钉法与红证纪律：规则钉整句、位置钉独占字面、红证必含反向审计

适用：仓内读 Markdown / 技能正文做「文件即契约」断言的 node:test 静态守护测试。先例：`test/unit/ci-workflow.test.ts`、`test/unit/docs-surface.test.ts`、`test/unit/research-linkage-static-guard.test.ts`。

## 事实

出处：票 20261123-e5b2 的评审 20261124-b40e。标准轴与 Spec 轴各自在内存里做删除与反转模拟（不写盘），得出以下五条。

1. **带箭头的条件规则只钉碎片，规则反转时测试仍绿。** 实例：「该 need 名下已有…的报告 → 读既有报告…不重跑检索、不另立报告」拆成条件半句与后果半句两个锚词；把后果改成「重跑检索、另立报告」后 0 条变红——条件半句被同文件另一条规则（§11.13「不重复触发」句）满足。
2. **同句在一份文件的两节各有一份时，删掉场景点名的那一份测试仍绿。** 实例：蓝图 §11.13 出口门禁与 §8 决策点全表 dev-clarify 行各有「报告尚未交付 → 建议 /dev-research 交付报告」。
3. **规格文档带修订记录时，修订记录逐字复述新句。** 读全文做正向断言，规格行全部回退、只留修订记录也是绿的。实例：承载锚词的 14 行规格行全删，朴素全文读取对 45 条蓝图锚词的 29 条仍命中。
4. **退役句的原句字面可能因括注差异成为空断言。** 实例：蓝图旧句括注内多一段「，need 0001 先例」，spec 给的负向锚词「变 FR（调研报告是交付物）」在改前的蓝图里就是零命中。
5. **只验证「改坏受守护文本能让测试变红」证明不了守护有效**——它回答不了「哪些回退不会让它变红」。同一次评审里，编排方的三次变异抽查全部变红，两轴的反向模拟却找出 3 条阻断、6 条同类遮蔽。

## 纪律

1. **规则钉整句**：带箭头（→）的条件规则，锚词取跨箭头的整句字面，不钉碎片。
2. **位置钉独占字面**：场景点名了具体位置、而同句在同文件另有一份时，接前文或按标点区分出该位置独有的字面。区分不了的才用出现次数，并在头注写明局限——次数钉法拦不住「删一份、别处加一份」。例：

   ```ts
   // 两处同句只差「留痕」后的一个右括号，各在蓝图规格行恰出现 1 次
   assertAnchored([blueprintSpec], ['`[trivial]` 留痕）；拍板不通过 → 不记账，说明差距并停在拍板点']);
   assertAnchored([blueprintSpec], ['`[trivial]` 留痕；拍板不通过 → 不记账，说明差距并停在拍板点']);
   ```
3. **规格行与修订记录分读取面**：正向锚只打规格行——整块剔除头部修订块，定位点缺失或剔除后仍有记录行即抛错，不静默；负向锚打全文。
4. **负向锚取退役句的稳定子串**：对该句的全部历史落点同取稳定子串，不取带括注的原句。
5. **红证必含反向审计**：除「改坏后变红」外，逐处删除每个正向锚词的每一处出现、逐个写回每个负向锚，全部变红才算守护成立；把边界写进测试头注——哪些位置受守护、哪些没有、清单是否穷尽。
6. **作者与评审者分离**：守护测试的评审者不与被守护文本的作者、实现者、编排方复用上下文。
7. **锚词来源与折行**：锚词取 spec 验收场景与实现决策的字面（期望值的独立来源）。受守护 Markdown 有硬折行时，比对前去掉两侧空白，或取不被折行切断的短锚；所选方式写进头注。

## 反例与修法

| 反例 | 识别信号 | 修法 |
|---|---|---|
| 碎片钉法 | 测试名写的是一条带箭头的规则，断言却是两个不含箭头的片段 | 换成跨箭头整句 |
| 同句遮蔽 | 删掉场景点名的那一份，测试仍绿 | 接前文钉独占字面 |
| 修订记录假绿 | 规格行回退、修订记录还在，正向断言仍绿 | 正向只打规格行，整块剔除并对残留抛错 |
| 空负向 | 负向锚词在改前的文本里就是零命中 | 取退役句的稳定子串 |
| 单向红证 | 红证只有「改坏后变红」 | 补逐处删除与逐个写回的反向审计 |
