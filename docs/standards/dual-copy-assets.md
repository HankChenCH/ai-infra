# 双份同步资产的一致性保障

本仓库多处存在"活本 + setup-workspace 生成资产"双份文件（`docs/METHOD.md` 与 `skills/setup-workspace/assets/METHOD.md`、两份 `GLOSSARY.md`、`.sdlc/check.sh` 与 assets 副本）。改动规则：

1. **双份文件必须有常驻逐字一致断言**（pytest 套件常驻回放的 `legacy_stream.py` 断言组，条目 id `run-tests.sh:3411–3417`，由 `test_migration.py` 执行；原 run-tests.sh `diff` 断言组随批 3 收口退役，留作 spec 0007 先例史注）。没有断言的双份文件必然漂移——GLOSSARY 曾在 need 阶段单边更新，直到断言落地才暴露九词条缺口。
2. **先观察红，再收口**：新增断言先跑出失败（漂移实证），同步后转绿；未见过红的断言不能证明它拦得住漂移。
3. **成文措辞与机械实现核对**：文档描述门禁行为（如 METHOD §7 validate 行）必须与脚本实际报错逐字核对（如 check.sh "spec 已置 done 但名下过程档未清扫"），不凭记忆转述。
4. **改动落在活本，同步用整文件复制**：`cp` 保持逐字一致，不做两边各改各的"等价修改"。
5. **枚举单点化**：同一枚举清单（目录集、状态词表、生命周期）正文只在一处穷举，他处引用而不重抄；无法单点的（机制层与模板层各需一份、或散文叙述确需重述），新增/修改枚举值时必须 grep 全库枚举点同批改——核对以 grep/diff 实测输出为准，不接受凭记忆声明（2026-11-07 门禁缺陷同根因教训：物化清单、状态词表、成文枚举多处散布，改三漏一；"经核无枚举面"凭记忆声明被评审证伪）。
6. **随包资产与发布面清单类枚举同步落守护测试**：发布态清单（如插件 prepack 的 `PUBLISHED_FILES`）、随包 `files` 声明等分发面枚举，新增/修改枚举值时与守护断言同批落（2026-11-22 教训：dsh-mcp 白名单三处逐字重抄改一漏二，主修复带红过提交门；守护测试 `test/unit/dsh-mcp-prepack-published-files.test.ts` 以「换载清单覆盖源码态声明资产」形态机械兜底）。同批 grep 范围含测试断言与日志文案，不只源码正源。
