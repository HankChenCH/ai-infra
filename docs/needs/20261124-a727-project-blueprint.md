# 项目蓝图能力——套件为消费项目提供项目级设计真相源

## 背景与业务目标

- 痛点（用户原话，2026-11-24）：「ADR 零散不关联，人对系统的理解缺乏总体认知」。套件消费项目的设计决策散在 need / spec / design / adr 各类轮次产物里，没有一个全项目视角的汇合点；新会话与新人理解项目要翻多个产物自行拼装。
- 参照隐喻（用户原话）：「在建筑工程中一般用建筑蓝图来固定建筑物的设计、架构，使得各个建筑施工部门能稳妥协作」。用户期望套件为消费项目提供同性质的东西：一张把项目设计固定下来的**项目蓝图**，作为后续人与智能体理解项目的入口与施工依据。
- 现状真空：套件已有的相邻能力都不承载此位——setup-reconstruct 面向存量代码逆向（向后看）、dev-design 是单 need/spec 轮次粒度、dev-overview 总览是过程档（终态清扫）、AGENTS.md 哨兵块讲流程不讲项目自身。全项目级、随开发演进的理解入口是空白。
- 业务目标（成功标准，用户原话，须可核销）：
  1. 全新 AI 会话经 AGENTS.md 蓝图指针定位到所做工作命中的**入口**，只读该入口主册 + AGENTS.md 即答该入口的核心设计问题（跨入口问题加读项目主册），不用翻轮次产物；更深的问题按入口主册目录打开对应分册——读分册仍属读蓝图。单入口退化形态下「入口主册」即项目主册。
  2. 新人接手项目时，AI 能解释当初的设计原则与考虑取舍。
- 不做的代价（用户原话）：长期软件工程质量跑偏。
- 服务对象形态：新立项项目（正向设计过程中长出蓝图）与存量项目接入（用户 2026-11-24 拍板「存量项目也要接入」）都要覆盖。
- 多应用入口（用户原话）：「对于一个项目，可能有多个应用入口，这些应该分开按入口分开蓝图。每个应用入口的蓝图的六类内容可能各不相同（因为使用者不同）」——蓝图顶层按入口组织，术语随之按入口归册。

## 干系人与用户

- 读者侧 Actor：
  - AI 新会话：接手消费项目任一工作的全新会话，读入口主册 + AGENTS.md 回答核心设计问题（成功标准 1）。
  - 新接手的人：借 AI 解释理解项目的设计原则与取舍（成功标准 2）。
  - 开发中的会话（施工读者）：写码 / 评审 / 验收的进行中会话把项目蓝图当**施工依据**读——蓝图是权威设计参照，不只是参观文档（用户拍板「是施工的依据」）。
- 生产侧 Actor（承载形态 = C）：
  - 蓝图维护技能（新）：创建 / 汇合 / 拆册 / 对账 / 术语迁移的单一 owner。
  - 既有技能薄联动点：dev-accept passed 蒸馏加蓝图回写支路；dev-design 置 ADR accepted 时亮牌蓝图待回写；setup-reconstruct 加存量汇合出口。
- 骨架诞生时机：新立项项目在 dev-design 分析形态走查批准后亮牌触发（此时有第一版三视图可汇）；存量项目在 setup-reconstruct 完成后亮牌触发汇合成首版；不绑 setup-workspace。亮牌是建议，用户可拒绝（对齐 dev-design 入口惯例）。

## 系统能力需求

- FR-1 **新立项蓝图诞生**：消费项目在 dev-design 分析形态走查批准后，蓝图维护技能亮牌建议创建蓝图骨架，用户确认后落盘项目主册 + 入口判定（来源：D12、D10、干系人骨架诞生时机）。
- FR-2 **存量蓝图汇合**：setup-reconstruct 完成后，维护技能亮牌建议汇合逆向产物（逆向 need / 逆向 ADR / 折叠内容）成首版蓝图，用户确认后落盘（来源：D4、D12）。
- FR-3 **按入口组织**：多入口项目蓝图 = 项目主册（入口索引 + 跨入口共享：全局架构原则、共享领域概念、跨入口决策）+ 每入口一套（入口主册 = 该入口六类内容 + 按需分册）；入口判据 = 有独立使用者群体的应用面（Web 端 / CLI / API 服务 / 管理后台…），清单由维护技能亮牌识别、用户拍板，禁止代挑；运行中长出新入口 = 亮牌立新入口套；单入口项目不建入口层，直接 = 项目主册 + 全局册 + 模块册（来源：D14、D16、多应用入口原话）。
- FR-4 **六类内容承载**：蓝图承载六类——项目定位与边界 / 领域模型与核心概念 / 架构分层与模块地图 / 关键设计决策及关联 / 术语 / 演进史（修订记录）；演进史 = 主册修订记录段（来源：D1、D15）。
- FR-5 **决策关联层**：蓝图决策节自含「现状 + 为什么 + 取舍」叙述，串接 ADR（含 superseded 链指针与指回 adr 文件路径）；ADR 保持独立成册，蓝图不收编 ADR（来源：D18、D6）。
- FR-6 **自适应分册**：内容超过尺寸阈值（主册或单分册 > 300 行）时维护技能亮牌建议拆册、用户拍板，不自动拆；拆册后主册目录与分册实体由维护技能对账（来源：D2、D5、D9、D11）。
- FR-7 **施工依据装载**：dev-implement 开工装载项目主册（仅跨入口改动时）+ 命中入口的入口主册 + 改动面命中的模块册（最小必要面）；dev-review / dev-accept 按需装载；AGENTS.md 项目速览区加蓝图指针一行（含入口索引），无技能会话也能定位（来源：D3、D13、D17）。
- FR-8 **随轮次保鲜**：dev-accept passed 的蒸馏能把该轮耐久变化（新决策、模块地图变化、新取舍）折进对应蓝图册；dev-design 置 ADR accepted 时亮牌蓝图待回写；蓝图与最新轮次产物冲突时以轮次产物为准，冲突标记为漂移信号、由回写消解（来源：D8、D12）。
- FR-9 **术语归册**：每入口主册含术语节（超阈值独立术语分册，自适应同规）；GLOSSARY.md 只留流程术语章 + 指针行；蓝图骨架诞生时维护技能把存量项目术语章迁入对应入口（归属模糊的术语亮牌 + 用户拍板）；迁移前（澄清期）新术语仍登记 GLOSSARY 项目术语章，蓝图诞生后新术语直接登记对应入口蓝图（来源：D15）。

## 场景

主流程：

- **S1 新立项蓝图诞生**：Given 消费项目已接入套件、dev-design 分析形态走查通过 / When 第一道 approved 门落定 / Then 维护技能亮牌建议立蓝图骨架，用户确认后项目主册 + 入口判定落 `docs/blueprints/`，AGENTS.md 加蓝图指针（FR-1、FR-3、FR-7）。
- **S2 施工装载**：Given 蓝图在盘、dev-plan 拆出带「改动面」的工票 / When dev-implement 开工 / Then 装载项目主册（仅跨入口改动）+ 命中入口主册 + 改动面命中模块册，实现以蓝图设计为权威参照（FR-7）。
- **S3 轮次回写保鲜**：Given 一轮 spec 验收 passed / When dev-accept 执行蒸馏 / Then 蓝图回写支路把新决策与取舍折进对应蓝图册，主册修订记录段追加一行（FR-8、FR-4）。
- **S4 存量汇合**：Given 存量项目跑完 setup-reconstruct（逆向产物在盘）/ When reconstruct 出口 / Then 维护技能亮牌汇合逆向产物成首版蓝图，GLOSSARY 存量项目术语章迁入对应入口（FR-2、FR-9）。

异常流：

- **E1 蓝图过期冲突**：新 ADR 取代旧决策而蓝图未跟上 → 以轮次产物为准，蓝图侧标记漂移信号，待回写消解（FR-8；拍板 D8）。
- **E2 超阈值**：主册或单分册超 300 行 → 亮牌建议拆册；用户拒绝拆 → 留痕继续（FR-6；拍板 D9）。
- **E3 蓝图未诞生时的新术语**：澄清期仍登记 GLOSSARY 项目术语章暂存，蓝图骨架诞生时随迁移归入对应入口（FR-9；拍板 D15）。
- **E4 入口判属争议**（一个应用面算不算独立入口 / 一条术语归哪个入口）：维护技能亮牌列候选，用户拍板，禁止代挑（FR-3、FR-9；拍板 D16）。

## 假设与风险

- R1 **联动漏改腐化风险**：蓝图保鲜依赖既有技能联动点全部接线（蒸馏支路 / ADR 亮牌 / reconstruct 出口）；任一漏改则蓝图回到「零散不关联」原点。缓解路径 = 治理文档先行（蓝图规格条目）+ 静态守护测试（套件先例：ci-workflow / codeup-projection-sync 两个测试）。**验证通过（验收 20261124-8b7c）**：治理先行提交序实证（蓝图条目提交先于技能落盘）；静态守护测试 test/unit/blueprint-wiring-static-guard.test.ts 落地（37 正向锚 + 8 负向族 + 双份资产逐字断言，18 测试），回退即红。
- R2 **入口判据边界模糊**：真实项目里应用面边界可能不清（如同一 Web 应用含用户端与管理后台）。处置已设计（E4 亮牌 + 拍板），但判定成本在多入口项目持续存在。**验证通过（机制文本面）/ 多入口实跑本轮未触发**：处置句在盘（dev-blueprint §3.2 + 蓝图 §11.25）；round 1 单入口退化，多入口持续判定成本留 round 2。
- R3 **阈值 300 行为初值**：尺寸阈值是拍板值而非实测值，spec 期可按样板项目实测校准；调整不改能力语义（FR-6 只依赖「有阈值 + 亮牌」）。**本轮未触发（实测校准未发生）**：初值 300 行按拍板落盘，调参缓冲设计在盘（「样板项目实测后可经后续轮次调参」），实测校准留样板项目首跑。

## 范围与非目标

- 范围：新立项项目与存量项目接入两条路都要有蓝图产出路径；存量路径蓝图来源 = setup-reconstruct 逆向产物汇合，不另起独立扫描。
- 蓝图内容六类清单：项目定位与边界 / 领域模型与核心概念 / 架构分层与模块地图 / 关键设计决策及关联 / 术语 / 演进史（修订记录）。
- 形态：自适应分册，切分轴 = 混合（项目主册 + 全局册 + 模块册，多入口时按 FR-3 扩展）；主册自含核心（定位、架构原则、关键决策 + 一句理由），分册叙述与取舍自含、实现细节索引指回轮次产物；尺寸阈值（> 300 行）亮牌建议拆 + 用户拍板；权威序 = 冲突时轮次产物为准、冲突即漂移信号。
- 承载与治理：承载形态 = 新蓝图维护技能 + 既有技能薄联动点；门禁地位 = 知识档轻产物，落 `docs/blueprints/`，无 frontmatter 状态机、不进 check.sh validate，主册目录 ↔ 分册实体对账归维护技能自查；施工装载按 FR-7。
- 多入口组织：结构 = 项目主册 + 每入口一套；术语治理 = 项目术语章迁入蓝图按入口归册、GLOSSARY 留流程术语章 + 指针行；入口判据与单入口退化按 FR-3。
- 非目标（建议清单，定稿念读时确认）：
  1. 不收编 ADR——ADR 保持独立成册（D18）；蓝图只做关联层与当前态视图。
  2. 不替代轮次产物——need / spec / design / ticket 照旧，蓝图是汇合视图与索引层（D8 权威序反推）。
  3. 不进 check.sh 状态机与 validate（D11）。
  4. 不自动拆册（D9）。
  5. 不绑 setup-workspace 初始化——骨架由维护技能在触发点亮牌（D12）。
  6. 不承载 UI 原型与设计稿——界面设计归 design-\* 套件与 docs/designs/assets/（六类清单未含，推断项，念读时确认）。
