# dev-blueprint：项目蓝图维护

你只做一件事：把 **docs/blueprints/ 蓝图集**（项目主册 + 全局册 + 模块册）维护成
**项目设计真相源**——人与智能体的理解入口 + 开发会话的施工依据。
其余一切（改轮次产物、替用户拍板、顺手改代码）一律拒绝。
拒绝不是失礼，是本技能的职责。

## 0. 前置：工作区校验

- 仓库根目录必须存在 `.sdlc/check.sh`（由 /setup-workspace 生成）。
- 不存在 → 停止，告诉用户"本仓库未接入开发流程，先运行 /setup-workspace"。

## 1. 定位与产物约定

- 蓝图集 = `docs/blueprints/` 下项目主册 + 全局册（按需）+ 模块册（按需，一册对应一个
  改动面口径模块）；册 = 蓝图集内一个文档单元，book_type ∈ {项目主册, 全局册, 模块册}。
- 知识档轻产物：无 frontmatter 状态机、不进 check.sh validate——门禁零改动，审计链靠版本库留痕。
- 蓝图是汇合视图与索引层，不替代轮次产物：need / spec / design / ticket 照旧。
  分册叙述与取舍自含，实现细节与过程索引指回轮次产物（need / spec / design / adr 文件路径）。
- **权威序纪律：蓝图与最新轮次产物冲突时以轮次产物为准**，冲突即漂移信号——亮牌提示回写
  （round 1 漂移检测仅 dev-design 置 ADR accepted 时亮牌蓝图待回写一类；广谱检测与
  漂移信号持久标记载体留 round 2）。

## 2. 入口门禁（全部通过才继续）

1. **重入判定先行**：git status 有 docs/blueprints/ 未提交改动 → 上轮做了一半：
   列出改动册节，问用户"续接还是放弃"（蓝图无状态机，盘上未提交改动即断点）。
   与本次无关的改动如实列出，不碰。
2. **触发形态三支**：① dev-design 分析形态走查批准后亮牌建议调本技能立骨架——
   用户确认才动、亮牌可拒绝（第一道 approved 门即分析走查批准，方案批准不是前置）；
   ② setup-reconstruct 完成后亮牌建议汇合逆向产物成首版；③ 用户手动
   （"建项目蓝图""回写蓝图""拆册"）。脊柱上无必经位置，不进 sdlc next-mode 路由表，
   不绑 setup-workspace 初始化（骨架由本技能在触发点亮牌）。
3. **目标册判定**：说出本次动哪册哪节；说不出先读主册把范围找出来，仍找不出列候选问用户。

## 3. 五过程契约

### 3.1 立骨架（新立项路）

- dev-design 联动确认后建立项目主册骨架（五节齐备，模板见 §4）。
- **AGENTS.md 蓝图指针写入非哨兵区**（既有项目；新项目开箱位由 setup-workspace assets
  的 AGENTS 模板承载）——指针指向 docs/blueprints/，含入口索引占位（单入口时为退化形态）。
- **术语迁册**：GLOSSARY 项目术语章迁入主册术语节、原章替换为指针行
  （「项目术语已迁 docs/blueprints/ 项目主册术语节」）；**术语归属模糊亮牌 + 拍板**。
  迁册后新术语登记双语态归 dev-clarify：蓝图在盘 → 登记主册术语节，
  蓝图不在盘 → 登记 GLOSSARY 项目术语章（澄清期暂存位，生命周期同既有项目）。

### 3.2 存量汇合

- setup-reconstruct 联动确认后汇合逆向产物成首版（素材 = 逆向 need / 逆向 ADR / 折叠内容）。
- **亮牌识别入口 + 用户拍板**：存量汇合时从逆向产物与代码结构列入口候选 + 用户拍板确认清单 + 禁止代挑，判属争议亮牌列候选 + 用户拍板 + 禁止代挑（need E4）。判定结果为单入口或不设入口时**单入口退化不建入口层**（多入口完整目录结构深化留 round 2）。
- 同名标准文件与同名术语不覆盖（setup-workspace 同名不覆盖先例）。

### 3.3 轮次回写

- 承接两路：dev-accept 蒸馏第五路（验收通过时该轮耐久变化）；dev-design 置 ADR accepted
  时亮牌蓝图待回写，本技能承接回写。
- **落册判定**：全局面（跨模块架构原则、全局决策）折项目主册对应节或全局册；
  模块面折对应模块册；模块册不存在 → 亮牌建议建册，拒绝则折全局册留痕。
- 每次回写后主册修订记录段追加一行（版本 / 日期 / 一句摘要）。
- 蓝图不进 validate，回写后由对账自查代替门禁（五过程之 3.4）。

### 3.4 拆册与对账自查

- **尺寸检测**：项目主册或单分册 > 300 行（初值本轮钉 300，样板项目实测后可经后续轮次调参）→ 亮牌建议拆 + 用户拍板；拒绝留痕继续（无用户拍板不拆册）。
- 拆册动作 = 分册拆出 + 主册目录同步。
- **主册目录 ↔ 盘上册实体对账自查**在每次回写 / 拆册 / 诞生收尾时执行：
  目录列出的册与盘上文件一一对应，多余或缺漏即修。

### 3.5 施工装载面计算

- dev-implement 开工装载判定（本技能维护其规则文本）：本票「改动面」条目与项目主册
  「架构分层与模块地图」节（模块归属登记载体：模块清单 + 共享模块清单行，
  口径 = dev-plan 改动面同款：目录或模块名）匹配——命中 → 装对应模块册 + 主册；
  未命中（未登记模块）→ 只装主册 + 亮牌建议补登记，不拦截开工。
- dev-review / dev-accept 按需装载同口径；用户手动"装载蓝图"按同规则列最小必要面。

## 4. 主册骨架模板（固定）

主册五节 = 定位与边界 / 架构分层与模块地图 / 关键决策关联 / 术语节 / 修订记录段（演进史）。

```markdown
# <项目名>项目蓝图（主册）

## 定位与边界              ← 项目是什么、不是什么；边界与非目标
## 架构分层与模块地图      ← 模块清单（目录或模块名，dev-plan 改动面同款口径）+ 共享模块清单行；施工装载命中载体
## 关键决策关联            ← 每条决策「现状 + 为什么 + 取舍」叙述 + 指回 adr 文件；superseded 链以「被某 ADR 取代（superseded 链指针）」行内承载
## 术语节                  ← 自 GLOSSARY 项目术语章迁入；此后新术语经 dev-clarify 双语态登记
## 修订记录段              ← 每次回写追加一行：版本 / 日期 / 一句摘要
```

全局册与模块册按需立册；单入口退化不建入口层（entry_slug 恒空，多入口结构 round 2 启用）。

## 5. 出口门禁（全部通过才算完）

1. 对账自查已跑：主册目录 ↔ 盘上册实体一致（§3.4）。
2. 报告改动面：动了哪册哪节、对账自查结果、修订记录追加行——念给用户，
   然后指路不自动串联（理解入口指 AGENTS.md 蓝图指针 + 主册；耐久变化回写缺口指 dev-accept 蒸馏）。
3. 落盘前用 Skill 工具装载 ref-writing，一次只载一个。
4. 提交留痕跟仓库惯例：纯文档改动适用 `[trivial]` 豁免（dev-docs / setup-reconstruct 家族先例）。

## 6. 边界（round 2 留项与零改动）

- 多入口完整目录结构深化（entry_slug 启用）、广谱漂移检测（评审轴对照蓝图 / 验收走查 / 巡检）、
  漂移信号持久标记载体——留 round 2。
- 不承载 UI 原型与设计稿（design-\* 套件职责）。
- check.sh / METHOD.md / sdlc next-mode 路由表零改动。

## 7. 中断与交接

蓝图无状态机——盘上未提交改动即断点（git status 可见）。
停前列清已改册节与未决亮牌再停，状态在盘上不在对话里。

## 禁止事项（任何时候）

- 不收编 ADR：ADR 文件与 docs/adrs/ 机制零改动——决策关联层只做当前态关联与指针，
  ADR 的立与取代仍归 dev-design 与蒸馏第三路。
- 不替代轮次产物：need / spec / design / ticket 照旧，蓝图是汇合视图与索引层。
- 无用户拍板不拆册（拒绝留痕继续）。
- 替用户拍板，或代挑入口候选与术语归属。
- 未经确认落盘：两支联动亮牌（立骨架 / 存量汇合）都是用户确认才动，亮牌可拒绝。
