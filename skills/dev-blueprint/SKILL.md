# dev-blueprint：项目蓝图维护

你只做一件事：把 **docs/blueprints/ 蓝图集**（项目主册 + 入口层 + 全局册 + 模块册）维护成
**项目设计真相源**——人与智能体的理解入口 + 开发会话的施工依据。
其余一切（改轮次产物、替用户拍板、顺手改代码）一律拒绝。
拒绝不是失礼，是本技能的职责。

## 0. 前置：工作区校验

- 仓库根目录必须存在 `.sdlc/check.sh`（由 /setup-workspace 生成）。
- 不存在 → 停止，告诉用户"本仓库未接入开发流程，先运行 /setup-workspace"。

## 1. 定位与产物约定

- 蓝图集 = `docs/blueprints/` 下项目主册 + 入口层（判定拍板为多入口时建）+ 全局册（按需）
  + 模块册（按需，一册对应一个改动面口径模块）；册 = 蓝图集内一个文档单元，
  book_type ∈ {项目主册, 入口主册, 全局册, 模块册}。
- **入口目录结构**：判定拍板为多入口 → `docs/blueprints/<entry-slug>/` 每入口一个子目录，
  入口主册 + 入口级分册（模块册 / 术语分册）落子目录，项目主册与项目级分册
  （跨入口共享模块册 / 全局册）留顶层；entry_slug 用 ASCII 小写短横线
  （对齐 claim slug 惯例），单入口退化恒空。
- **共享面判定**：跨入口共享内容归项目主册或项目级分册（共享判据：全局架构原则、
  共享领域概念、共享模块与共享决策）；入口主册六类内容自治（含入口专属术语节），不重复。
- 知识档轻产物：无 frontmatter 状态机、不进 check.sh validate——门禁零改动，审计链靠版本库留痕。
- 蓝图是汇合视图与索引层，不替代轮次产物：need / spec / design / ticket 照旧。
  分册叙述与取舍自含，实现细节与过程索引指回轮次产物（need / spec / design / adr 文件路径）。
- **权威序纪律：蓝图与最新轮次产物冲突时以轮次产物为准**，冲突即漂移信号——漂移信号
  持久载体 = 项目主册「待回写漂移」标记行区（仪表盘语义，契约见 §4）：检测者（装载 /
  走查会话）发现即写行，不经本技能转手；标记行是元数据不是蓝图内容，册内容写者纪律不变。
  漂移检测三处：dev-implement 开工装载对照发现即写行、dev-accept 使用方走查轴对照发现
  即写行并留痕报告、本技能回写自查集中亮牌；dev-design 置 ADR accepted 亮牌蓝图待回写
  一类承前不变。

## 2. 入口门禁（全部通过才继续）

1. **重入判定先行**：git status 有 docs/blueprints/ 未提交改动 → 上轮做了一半：
   列出改动册节，问用户"续接还是放弃"（蓝图无状态机，盘上未提交改动即断点）。
   与本次无关的改动如实列出，不碰。
2. **触发形态三支**：① dev-design 分析形态走查批准后亮牌建议调本技能立骨架——
   用户确认才动、亮牌可拒绝（第一道 approved 门即分析走查批准，方案批准不是前置）；
   ② setup-reconstruct 完成后亮牌建议汇合逆向产物成首版；③ 用户手动
   （"建项目蓝图""回写蓝图""拆册"）。脊柱上无必经位置，不进 sdlc next-mode 路由表，
   不绑 setup-workspace 初始化（骨架由本技能在触发点亮牌）。
3. **目标册判定**：说出本次动哪册哪节；说不出先读主册把范围找出来，仍找不出列候选问用户。

## 3. 五过程契约

### 3.1 立骨架（新立项路）

- dev-design 联动确认后建立项目主册骨架（**主册七段**齐备，模板见 §4）。
- **入口判定**（亮牌识别入口 + 用户拍板）：亮牌列入口候选 + 用户拍板确认清单 + 禁止代挑，
  判属争议亮牌列候选 + 用户拍板 + 禁止代挑（need E4）；判定结果为单入口或不设入口时
  单入口退化不建入口层（主册仍含待回写漂移标记行区，入口索引节标「单入口退化」）；
  拍板为多入口 → 每入口建 `docs/blueprints/<entry-slug>/` 子目录落入口主册 + 入口级分册。
- **AGENTS.md 蓝图指针写入非哨兵区**（既有项目；新项目开箱位由 setup-workspace assets
  的 AGENTS 模板承载）——指针指向 docs/blueprints/，多入口时指针含真实入口索引
  （入口清单逐项列出），单入口为退化形态。
- **术语迁册**：GLOSSARY 项目术语章迁入主册共享术语节、原章替换为指针行
  （「项目术语已迁 docs/blueprints/ 项目主册共享术语节」）；共享术语登记主册共享术语节、
  入口专属术语登记对应入口主册术语节，**术语归属模糊亮牌 + 拍板**。迁册后新术语登记
  双语态归 dev-clarify：蓝图在盘 → 登记命中入口的入口主册术语节（共享术语登记主册
  共享术语节，判属争议亮牌），蓝图不在盘 → 登记 GLOSSARY 项目术语章（澄清期暂存位）。

### 3.2 存量汇合

- setup-reconstruct 联动确认后汇合逆向产物成首版（素材 = 逆向 need / 逆向 ADR / 折叠内容）。
- 入口判定与落子目录按 §3.1 同口径（从逆向产物与代码结构列入口候选）；
  判定为单入口或不设入口时按退化形态处置（不建入口层）。
- 同名标准文件与同名术语不覆盖（setup-workspace 同名不覆盖先例）。

### 3.3 轮次回写

- 承接两路：dev-accept 蒸馏第五路（验收通过时该轮耐久变化）；dev-design 置 ADR accepted
  时亮牌蓝图待回写，本技能承接回写。
- **落册判定**：全局面（跨模块架构原则、全局决策）折项目主册对应节或全局册；
  模块面折对应模块册；模块册不存在 → 亮牌建议建册，拒绝则折全局册留痕。
- 每次回写在主册「修订记录段」追加一行（版本 / 日期 / 一句摘要）。
- **回写自查**：每次回写收尾核对主册待回写漂移标记行区，未消解行集中亮牌逐行处置——
  消解动作按 §4 契约执行（留痕 + 修订记录追加一行）；当场处置不了的行如实留待，不带病关账。
- 蓝图不进 validate，回写后由对账自查代替门禁（五过程之 3.4）。

### 3.4 拆册与对账自查

- **尺寸检测**：项目主册或单分册 > 300 行（初值本轮钉 300，样板项目实测后可经后续轮次调参）→ 亮牌建议拆 + 用户拍板；拒绝留痕继续（无用户拍板不拆册）。
- 拆册动作 = 分册拆出 + 主册目录同步。
- **主册目录 ↔ 盘上册实体对账自查**（含入口索引 ↔ 盘上入口子目录）在每次回写 / 拆册 /
  诞生收尾时执行：目录列出的册与盘上文件一一对应，多余或缺漏即修。

### 3.5 施工装载面计算（按入口装载三支）

- dev-implement 开工装载判定（本技能维护其规则文本）：本票「改动面」条目与项目主册
  「架构分层与模块地图」节匹配——登记载体：模块清单每行带入口归属（模块 → 入口 slug
  映射）+ 共享模块清单行，共享模块行标「共享」；口径 = dev-plan 改动面同款：
  目录或模块名。命中入口集三支：
  - **命中恰一入口 → 装项目主册 + 该入口主册 + 命中模块册**；
  - **命中多入口（跨入口改动）→ 装项目主册 + 各命中入口主册 + 命中模块册**；
  - **未命中（未登记模块）→ 只装项目主册 + 亮牌建议补登记，不拦截开工**。
- 装载对照发现蓝图册与最新轮次产物冲突（模块地图与实际改动面失配、决策被新 ADR 取代等）
  → 发现即写主册标记行区标记行并亮牌告知（行格式见 §4）。
- dev-review / dev-accept 按需装载同口径（多入口时按需 = 命中入口主册）；
  用户手动"装载蓝图"按同规则列最小必要面。

## 4. 主册骨架模板（固定）与标记行区契约

主册七段 = 定位与边界 / 入口索引 / 架构分层与模块地图 / 关键决策关联 / 共享术语节 /
修订记录段 / 待回写漂移标记行区。

```markdown
# <项目名>项目蓝图（主册）

## 定位与边界              ← 项目是什么、不是什么；边界与非目标
## 入口索引                ← 入口 slug → 使用者群体一句 → 子目录指针；单入口退化时节标「单入口退化」
## 架构分层与模块地图      ← 模块清单每行带入口归属（目录或模块名，dev-plan 改动面同款口径）
                             + 共享模块清单行（标「共享」）；施工装载命中载体
## 关键决策关联            ← 跨入口共享决策；每条决策「现状 + 为什么 + 取舍」叙述 + 指回 adr 文件；
                             superseded 链以「被某 ADR 取代（superseded 链指针）」行内承载
## 共享术语节              ← 跨入口共享概念（GLOSSARY 项目术语章迁入；此后新术语经 dev-clarify
                             双语态登记）；入口专属术语在各入口主册术语节
## 修订记录段              ← 每次回写追加一行：版本 / 日期 / 一句摘要
## 待回写漂移              ← 标记行区（仪表盘语义，契约见下），检测者发现冲突即写行
```

多入口时每入口另立入口主册（形态同主册对应节，含入口专属术语节）+ 入口级分册落
`docs/blueprints/<entry-slug>/` 子目录；全局册与模块册按需立册；单入口退化不建入口层
（entry_slug 恒空）。

**待回写漂移标记行区契约**：
- 行格式 = `- [待回写] <发现点> → <冲突对象引用>（<日期>）`；检测者发现蓝图与最新轮次
  产物冲突即写行，不经本技能转手。
- 回写消解后该行改 `- [已消解 <日期>] <原行内容>` 留痕 + 主册修订记录段追加一行。
- 标记行是元数据不是蓝图内容；检测者只写标记行区，册内容写者纪律不变
  （叙述与决策关联仍只由本技能与蒸馏第五路动笔）。
- 权威序不变：冲突以轮次产物为准。

## 5. 出口门禁（全部通过才算完）

1. 对账自查已跑：主册目录 ↔ 盘上册实体一致（§3.4）。
2. 报告改动面：动了哪册哪节、对账自查结果、标记行区处置结果（新增 / 消解各行）、
   修订记录追加行——念给用户，然后指路不自动串联（理解入口指 AGENTS.md 蓝图指针 +
   主册；耐久变化回写缺口指 dev-accept 蒸馏）。
3. 落盘前用 Skill 工具装载 ref-writing，一次只载一个。
4. 提交留痕跟仓库惯例：纯文档改动适用 `[trivial]` 豁免（dev-docs / setup-reconstruct 家族先例）。

## 6. 边界（零改动与不在本技能面）

- 不承载 UI 原型与设计稿（design-\* 套件职责）。
- check.sh / METHOD.md / sdlc next-mode 路由表零改动。
- 拆册阈值 300 行实测校准留样板项目首跑（调参经后续轮次）。

## 7. 中断与交接

蓝图无状态机——盘上未提交改动即断点（git status 可见）。
停前列清已改册节与未决亮牌再停，状态在盘上不在对话里。

## 禁止事项（任何时候）

- 不收编 ADR：ADR 文件与 docs/adrs/ 机制零改动——决策关联层只做当前态关联与指针，
  ADR 的立与取代仍归 dev-design 与蒸馏第三路。
- 不替代轮次产物：need / spec / design / ticket 照旧，蓝图是汇合视图与索引层。
- 无用户拍板不拆册（拒绝留痕继续）。
- 禁止替用户拍板；禁止代挑入口候选与术语归属。
- 未经确认落盘：两支联动亮牌（立骨架 / 存量汇合）都是用户确认才动，亮牌可拒绝。
